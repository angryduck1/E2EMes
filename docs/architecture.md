# Architecture of Project.

## Client-Server Cryption

Сryptography module provides end-to-end encryption (E2EE) between the server and the client using key exchange and symmetric encryption primitives (based on the libsodium / crypto library standard).

- General cryption protocol server-client [CRYPTION](../cryption.h)

```text
       [ Client ]                                     [ Server ]
   generate_client_keypair()                      generate_server_keypair()
           │                                              │
     Client Public Key ──────────────────────────────────>│
           │<────────────────────────────────── Server Public Key
           │                                              │
generate_client_session_keypair()             generate_server_session_keypair()
           │                                              │
   [Session Keys (rx/tx)]                         [Session Keys (rx/tx)]
           │                                              │
           ├─── encode(msg, tx, nonce) ──────────────────>│
           │                                              └─── decode(msg, rx, nonce)
```

## Authorization
### There are 3 cases of authorization:

- Registration new account
- Login in exist account
- Login via **session-token**

## Three levels of security

- A master key is created during account registration. Master key - is the 12 symbols generated by [BIP_39](../client/bip_39.h). It`s look like *hunt ivory turn caution riot swallow stick banana payment awesome waste gun*
- A session-password is entered during account registration. 
- A account-password is entered during account registration.

Session token is automatically loaded from local storage:
```cpp
SessionData token =
    load_session_token_master_key("session_token.data");
```

Master key is never stored directly. Instead, a deterministic key pair is derived from the BIP-39 seed phrase and used to recover account access on new devices

[CLIENT LOGIN](../client/client_main.cpp)

- **save_session_token_master_key()** — creates a new master key and stores an encrypted session token.
- **save_session_token_load_master_key()** — restores an account using the master key and stores a new encrypted session token.
- **load_session_token_master_key()** — decrypts and loads a previously saved session token for automatic login.

## Server Manage

[SERVER MAIN](../server/server_main.cpp)

- After successful authorization, the server creates a dedicated thread for handling the client connection.

```cpp
connections.client_thread(new_session_id, cryption, session, socket, redis);
```


- Session tokens are generated using cryptographically secure random values.
- User and session metadata are stored in **Redis**.
- Chats are storage in **SQLite** base

## Connections

[CONNECTIONS](../server/connections.cpp)

- **Connections** is a base class for managing connected clients.
- Provides encrypted packet transmission using the Cryption module.
- Manages active sessions and client activity timestamps.
- Handles chat creation, message delivery and client synchronization.
- Stores message history in **SQLite** and session metadata in Redis.
- Automatically removes inactive sessions and closes dead connections.

```text
| Function | Description |
|----------|-------------|
| `send_package()` | Encrypts and sends a packet to a client. |
| `recv_package()` | Receives and decrypts a packet from a client. |
| `client_thread()` | Main client handler loop. Processes all client requests. |
| `new_chat()` | Creates a new chat request between users. |
| `new_message()` | Stores and forwards encrypted messages. |
| `sync_client()` | Synchronizes chats and message history with a client. |
| `add_session()` | Registers a new active session. |
| `update_activity()` | Updates client activity timestamp. |
| `clean_disconnected()` | Removes inactive sessions and closes dead connections. |
```

## Client base class

[CLIENT_ACTIVITY](../client/client_activity.cpp)

`ClientActivity` is the base class for managing client-side actions. It holds references to
`Session`, `Cryption`, `tcp::socket`, the password hash, and the key pair. On destruction,
it performs `sodium_memzero` on all shared keys and the password hash.

### Threads and main loop

```cpp
ClientActivity::main_thread()   // main thread; spawns input_thread as detached
ClientActivity::input_thread()  // blocking getline(cin) → sets newInput flag
```

`main_thread` runs an infinite loop and on each iteration:

1. If `newInput == true` — processes the command from stdin and resets the flag.
2. If `time_out_activity()` fires (20 s of inactivity) — sends a heartbeat `code 500`.
3. If `time_out_sync_activity()` fires (5 s) — calls `sync_cloud()`.

### Synchronization — `sync_cloud()`

#### Runs every 5 seconds. Three phases:

* new chats queue  → accept or reject incoming chat requests (y/n)
* chat list sync   → compare local message_id with the server's, request the delta
* message stream   → receive missing messages, decrypt them, write to the database
